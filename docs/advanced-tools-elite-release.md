# Advanced Tools Elite Release

## Release standard

This release is complete only when every advanced tool earns ten points out of ten across the website and iPhone app.

1. Human input: no code, JSON, internal identifiers, or schema language is visible.
2. Guided decisions: known choices use clear selection controls with an Other path.
3. Useful context: every field explains what belongs there in customer language.
4. Honest progress: generation shows a named stage, elapsed time, and a clear still working state.
5. Trusted result: output is readable, structured, copyable, and appropriate for the tool.
6. Continuity: nonclinical work is saved and available on both surfaces.
7. Safety: clinical workflows remain deidentified, ephemeral, and subject to qualified review.
8. Accessibility: controls have labels, state, touch targets, focus behavior, and live progress announcements.
9. Reliability: guided values always build a payload accepted by the existing API schema.
10. Parity: the same workflow title, promise, inputs, progress, and result contract appear on web and iPhone.

Any score below ten blocks release approval.

## Release gates

1. Shared experience contract covers every registered advanced tool.
2. Contract tests prove every guided payload passes the current Zod schema.
3. Automated checks reject customer facing JSON, structured data language, and learner identifiers.
4. Web typecheck, iPhone typecheck, API tests, web contracts, native contracts, build checks, and release gates pass.
5. Visual review covers small and large iPhone screens plus the main responsive web widths.
6. Device review confirms choices, Other input, keyboard flow, progress announcements, result scrolling, saved outputs, and cross surface continuity.
7. Clinical workflows confirm deidentified entry, ephemeral behavior, watermarks, and qualified review messaging.
8. TestFlight is created only after the code and visual gates pass.

## Required proof

The release owner records the commit SHA, successful CI run, visual review screenshots, device checklist result, TestFlight build number, production smoke result, and final sign off. A build existing in TestFlight is not proof that the experience passed.
